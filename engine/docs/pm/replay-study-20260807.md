## 1. 12戦を貫く構造（4解析が独立に同一結論）

**勝ちターンは全試合で同一アルゴリズム**だった（m14 T15 / m15 T10 / m16 T17 / m17 T11・T13 / m19 T10 / m20 T14・T16 / m21 T19 / m22 T13 / m23 T9 / m24 T12 / m25 T10）:

1. **無力化を先に**: 相手のアクティブブロッカー/リダイレクトを、レスト付与・凍結・ブロック不可化・または「素の打点で強制ブロックさせKO」で潰す（詰めターンの最初の行動）。
2. **剥がしを中間に**: 「相手が2枚消費で止まるサイズ」の素〜+1ドン攻撃を連打して手札カウンターを枯らす。止められてよい攻撃から宣言する。
3. **本命は最後・ドンは後置き**: 防御情報（ブロック/カウンターの出方）が確定してから残ドンを1本に全付与。最終打点は「相手リーダー実効+残手札のカウンター実測値+同値勝ち考慮」で**ぴったり〜圏外**に設計（m14は8000だと生存された9000、m17は理論最大+6000でも届かない18000）。
4. **防御は経済**: 勝者のカウンター消費 8000/1000/5000/13000級 vs 敗者 18000/7000/19000級（全試合で少ない側が勝ち）。優先度=①捨てられるブロッカー ②ライフ受け ③手札カウンター。ブロックには「ブロッカーが生還するちょうど+1000」だけ添える。キャラ護衛のカウンターは原則切らない（m16敗着: 壁護衛に7枚→結局KO→手札1枚で最終ターン）。
5. **例外則＝対ランプアグロの前倒し**: 相手の要求額がターン毎に単調増加する（ドン加速/ダブルアタック視認）場合は「2000で止まる今止める」（m22敗着: T9の2連スルー→T13に11000が数学的に受け不能）。

## 2. E61候補（統合・格付け）

### S級（複数試合で決定打・実装仕様が明確）

- **E61-1 詰めターンの攻撃順序テンプレ（E55 order の再設計形）**
  発火: `cpuCanLethal 近傍（期待ヒット≥相手残ライフ+1）or 相手ライフ≤1`。
  部品: ①無力化手段（レスト付与/凍結/ブロック不可）を攻撃列の**前**に消化 ②中間攻撃は「素でブロッカーを倒せる/相手が2枚要求で止まるサイズ」のみ素で宣言（E55 order が退行した原因="倒せない素"を混ぜた） ③最終1本に残ドン全付与・打点式は E61-2。
  証拠: 全12戦の勝ちターン。実装: cpuTurn の攻撃フェーズ序列＋cpuPickAttack。
- **E61-2 リーサル打点式と「殺しきり判定」**
  最終攻撃打点 ≥ 相手リーダー実効 + **残手札のカウンター実測推定**（枚数×1000〜2000＋公開済みイベント）+ 同値勝ち補正。満たせないなら攻め待ち（m14 T13: 攻撃0で盤面再建→T15一括）か本数圧殺（m25 T6: 5連×素6000）へ切替。marginmax（×2000上限）の precision 版＝1000刻みの割当不能を突く（m14実例: 資源18000 vs 要求17000でも割当不能で敗北）。
- **E61-3 防御経済の書き換え（E55 reko/alloc の正しいゲート形）**
  ①手札カウンターは最後の通貨（ブロック>ライフ>カウンター） ②ブロック時は「ブロッカー生還のちょうど+1000」のみ添える（m21: 8000ブロッカーが6回ブロック無傷） ③キャラ護衛は「消費≤再調達コスト」の時だけ ④**now-or-never**: 相手がランプ/D.Atk型でライフ≤3なら安い攻撃(≤2000)は今止める ⑤**ライフ下限=相手の次ターン最大打点Lmax**を割る受けは拒否 ⑥残る止め手<残る致死攻撃数なら無駄カウンター抑止（m22 T13）。実装: cpuCounter＋requiredReserveSim の Lmax 接続。
- **E61-4 KO対象の「継続価値」採点（utilko 拡張）**
  加点対象に ①ETBドロー/サーチ等のエンジンキャラ（m20: 8体駆逐が敗→勝の最大因子） ②毎ターン再生する壁（キッド型=「壁1残存=毎ターン攻撃1本無効」） ③レストコスト供給フォダー（対ミホーク型） ④デバフ済みキャラは**元パワー/元コスト基準**で採点し最小打点（リーダー可）で回収（m20 T12・m21 T17: リーダー6000で9000壁を処理）。
- **E61-5 リアクティブ・リーダー効果の汎用化（lucy/ace ハードコードの置換）**
  【相手のアタック時】系パンプ/軽減は ①止めない攻撃に使わない ②【ターン1回】は止める攻撃にだけ ③cpuCounter の壁計算に算入 ④攻め側は「相手の残アクティブドン＋リーダー効果上限」を数え、無料防御圏内の攻撃を打たない（S3拡張・E55 pump の一般形。m16: 素5000×3がドンレストで無料に消された）。

### A級（明確・条件付き）

- **E61-6** ブロッカー健在時の最大パンプ禁止（kocap の攻撃版。m16 T14: 11000先打ち→6000チャンプで6ドン損）

- **E61-9** 起動経済の皆勤（リーダー/キャラのドン回復・加速系起動を毎手番消化。ドン返却誘発チェーン=実質コスト負も接続）

## 3. 測定の設計メモ

- E55 の教訓どおり「第一形の単一ゲート移植」は退行する。E61-1〜3 は上記の複合ゲートを**初期形に含めて**実装し、heur2+OPCG_H2 単離 → 2帯 → 実利用対面（対ヤマト/対青緑ルフィ）クロスで測る（E60 で採用バーに追加済み）。
- E61-3/5 は対人間部品（CPU対CPU測定に写りにくい）＝「勝率中立＋明確な無駄手削減」基準（E54 kohand 型）を併用。
- 共通部品として先に作る: **相手カウンター資源の推定器**（枚数×平均値＋使用履歴＋公開情報）と **相手の次ターン最大打点 Lmax 推定器**（E61-2/3/8 が共用）。
